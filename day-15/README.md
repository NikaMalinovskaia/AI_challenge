# 🚦 День 15: Контролируемые переходы состояний (State Machine Guardrails)

На этом этапе мы объединяем конечный автомат (FSM) из Дня 13 и жесткие правила/инварианты из Дня 14 в единую систему **безопасности переходов (Guardrails)**. Агент не просто «знает» этапы жизненного цикла задачи, он физически застрахован от недопустимых прыжков по графу состояний.

---

## 🎯 Цели проекта
1. **Строгие состояния задачи:** Определение четких этапов (`planning ➔ execution ➔ validation ➔ done`).
2. **Матрица разрешенных переходов:** Программный запрет на «перепрыгивание» этапов (например, нельзя перейти из планирования сразу в валидацию или завершение).
3. **Безопасное управление:** Разделение логики чата (текстовый диалог) и логики FSM (контролируемые переходы через интерфейс управления).
4. **Персистентность и паузы:** Полное сохранение текущего этапа и контекста в JSON-файлах на диске, позволяющее бесшовно продолжить работу после перезапуска приложения.

---

## 🛠️ Архитектура и файлы проекта

* **`agent.py`** — Класс `GuardedFSMAgent`, управляющий системными промптами, историей короткой памяти (`short_term`), рабочим состоянием (`working` с текущим этапом `stage`) и инвариантами (`invariants`). Содержит метод `change_stage()`, проверяющий валидность переходов по матрице `ALLOWED_TRANSITIONS`.
* **`app.py`** — Интерфейс на базе **Streamlit** с боковой панелью управления («В Execution», «В Validation», «Завершить (Done)», «Вернуть в Planning») и чат-взаимодействием.
* **`memory_storage_day15/`** — Директория с JSON-файлами состояния, обеспечивающая персистентность данных между сессиями.

## 🚀 Быстрый старт

1. Установите зависимости (если еще не установлены):
   ```bash
   pip install streamlit openai
   ```
2. Убедитесь, что у вас настроена переменная окружения с API-ключом:
```
export LITELLM_API_KEY="ваш_ключ"
```

3. Запустите веб-приложение:
```
streamlit run app.py
```
### 🧪 Сценарий тестирования (Проверка задания)
1. Проверка недопустимого перехода:
- При старте приложения вы находитесь на этапе PLANNING.
- Попробуйте нажать кнопку «➡️ В Validation» или «🏁 Завершить (Done)» (либо напишите в чат с просьбой пропустить этап).
- Результат: Система выдаст ошибку безопасности FSM, так как граф состояний разрешает переход из planning только в execution.
2. Легальный переход и прохождение цепочки:
- Нажмите кнопку «➡️ В Execution». Статус изменится на EXECUTION.
- Затем нажмите «➡️ В Validation» — переход будет успешно разрешен.
3. Проверка устойчивости к паузе:
- Закройте терминал (остановите приложение через Ctrl + C) и закройте вкладку в браузере.
- Запустите приложение заново (streamlit run app.py).
- Результат: Агент и интерфейс мгновенно восстановят актуальный этап (validation) и стек из файлов на диске без потери контекста.

### 🏆 Итог архитектурной серии
Пройдя путь от простой краткосрочной памяти до защищенного конечного автомата, мы создали надежного, безопасного и предсказуемого AI-ассистента, пригодного для интеграции в реальные бизнес-процессы с жесткими требованиями к качеству выполнения задач.
