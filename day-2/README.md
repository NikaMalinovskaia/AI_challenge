## Day 2: Python CLI с контролем ответа и валидацией JSON

CLI-скрипт отправляет запросы в корпоративный LiteLLM API и позволяет управлять техническими ограничениями ответа, режимами генерации и строгой валидацией через флаги командной строки.
Конфигурация
Скрипт читает переменные окружения из файла .env в корне проекта:

```
LITELLM_API_KEY=<ваш корпоративный API key>
```

## Внутренние настройки модели и шлюза, заданные в коде:
- API Base URL: [https://llm.effective.land/v1](https://llm.effective.land/v1)
- Model: deepseek-v4-flash-0731
- Timeout: 60s
- Temperature: 0.7 (в свободном режиме) / 0.1 (в контролируемом режиме)
- Max Tokens: 2000 (для обеспечения стабильности рассуждений и генерации)

## Флаги
- --mode — режим работы утилиты. 
Поддерживает два значения: free (свободный текст) или controlled (структурированный JSON с валидацией). 
По умолчанию: free.
- --prompt — текст пользовательского запроса. Если флаг не задан или оставлен пустым, промпт автоматически читается из стандартного потока ввода (stdin).

## Обычный режим (free)
Без флага --mode controlled (или при выборе --mode free) скрипт отправляет обычный запрос и печатает развернутый текстовый ответ модели (например, рецепт блюда с разметкой):
```
python3 main2.py \
  --mode free \
  --prompt "Напиши рецепт приготовления сырников"
```
Промпт можно передать через стандартный поток ввода (stdin / пайп):
```
echo "Напиши рецепт приготовления сырников" | python3 main2.py --mode free
```

### Controlled JSON режим
Флаг --mode controlled включает защищенный режим. Модель получает системную инструкцию отвечать исключительно в формате валидного JSON-массива без маркдауна, тегов code fence и пояснений вне структуры.
Ожидаемая схема ответа (список ингредиентов):
JSON
```
[
  {
    "name": "Название ингредиента",
    "weight": "Вес или объем",
    "step_order": 1
  }
]
```

После получения ответа скрипт выполняет локальную валидацию:
1) Очищает строку от возможных markdown-оберток (```json).
2) Производит десериализацию через json.loads.
3) Проверяет, что корневой элемент является массивом (list).
4) Проводит глубокую проверку каждого объекта: наличие обязательных полей (name, weight, step_order) и соответствие их типов (str, int).
5) В stdout выводится исключительно отформатированный и проверенный JSON.
Пример использования:
```
python3 main2.py \
  --mode controlled \
  --prompt "Как приготовить пасту карбонара"
```
Передача запроса через stdin в controlled-режиме:
```
echo "Как приготовить пасту карбонара" | python3 main2.py --mode controlled
```

## Обработка ошибок и краевые случаи
Если модель возвращает пустой контент (None) из-за исчерпания лимитов или сбоя шлюза, скрипт перехватывает это состояние, выводит понятное сообщение в stderr и завершается с кодом ошибки (exit 1).
Если структура ответа нарушена (модель принесла текст вместо JSON, пропустила поле или перепутала типы данных, например, передала строку вместо числа в step_order), блок валидации перехватывает ValueError / JSONDecodeError, выводит детали несовпадения и сырой ответ модели для отладки.
