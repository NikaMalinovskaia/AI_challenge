# 🔥 AI Challenge — День 31. Ассистент разработчика

Автономный AI-ассистент разработчика, интегрированный с контекстом локального и удаленного Git-репозитория (`NikaMalinovskaia/AI_challenge`), а также локальным LLM-окружением Ollama.

---

## 🎯 Цели и задачи дня
- **Контекст проекта:** Интеграция с документацией и деревом файлов репозитория.
- **MCP Tooling (Git):** Получение текущей локальной ветки Git, статуса рабочей директории и информации о файлах репозитория.
- **Команда `/help`:** Быстрая выдача сводки о проекте, ветке и текущем состоянии файлов.

---

## 🛠 Архитектура решения

Решение состоит из трех ключевых модулей:

1. **`mcp_git.py`** — модуль интеграции с внешней средой и Git:
   - `get_git_branch_info()`: Выполняет локальные команды `git branch` и `git status`, возвращая активную ветку и статус рабочей директории.
   - `get_github_repo_tree(path)`: Запрашивает дерево файлов и папок репозитория `NikaMalinovskaia/AI_challenge` через GitHub REST API.
   - `read_github_file(file_path)`: Загружает и декодирует содержимое конкретных файлов.

2. **`agent_dev.py`** — ядро AI-ассистента (`DevAssistantAgent`):
   - Перехватывает команду `/help` и мгновенно отдает структурированную справку по проекту без задержек на лишнюю генерацию.
   - Динамически извлекает контекст файлов из папок репозитория при упоминании пользователем конкретных директорий (например, `day-2`, `day-30`).
   - Собирает единый системный промпт с Git-контекстом и передает его в Ollama API (`http://localhost:11434/api/generate`).

3. **`app_dev.py`** — пользовательский веб-интерфейс на Streamlit:
   - Предоставляет чат с поддержкой истории диалога, отображением времени выполнения запроса и кнопкой очистки памяти.

---

## 📁 Структура проекта

| Файл | Описание |
|------|----------|
| `mcp_git.py` | MCP-инструменты для получения данных из Git и GitHub API. |
| `agent_dev.py` | Логика ассистента, обработка команды `/help` и взаимодействие с LLM. |
| `app_dev.py` | Web-интерфейс на Streamlit для взаимодействия с ассистентом. |
| `README.md` | Документация и отчет по Дню 31. |

## 🚀 Запуск и проверка

### 1. Установка зависимостей
```bash
pip install requests streamlit
```

### 2. Запуск локального LLM-сервера
Убедитесь, что Ollama запущен локально с нужной моделью (например, `qwen2.5`):
```bash
ollama run qwen2.5
```

### 3. Запуск веб-интерфейса
```bash
streamlit run app_dev.py
```

## 🧪 Пример использования

1. **Команда `/help`:**
   В чате введите `/help`. Ассистент мгновенно вернет справку с текущей веткой Git, статусом репозитория и структурой корневой директории.
   
2. **Вопрос о структуре проекта:**
   Введите запрос: *«Покажи файлы в day-30»* или *«Что находится в папке day-2?»*.
   Ассистент автоматически извлечет список файлов из указанной директории GitHub и даст подробный ответ на русском языке.
