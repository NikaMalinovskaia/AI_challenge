## День 5: Сравнение версий моделей (Weak, Medium, Strong)
Практическое исследование того, как производительность, скорость, ресурсоёмкость и качество ответов языковых моделей зависят от их архитектуры и размера. Эксперимент полностью автоматизирован с помощью скрипта на Python и универсальной библиотеки LiteLLM.

## Суть задания
Для выполнения задачи один и тот же тестовый промпт отправляется на три разные модели, выбранные из разных сегментов каталога Hugging Face:
1) Слабая модель (Weak): Компактная мини-модель из начала каталога (например, gemma-2-2b-it).
2) Средняя модель (Medium): Сбалансированная рабочая лошадка из середины каталога (например, Mistral-7B-Instruct).
3) Сильная модель (Strong): Тяжелый флагман или модель с глубоким анализом (например, Meta-Llama-3-70B-Instruct).

## Что замеряется:
- Время ответа в секундах с высокой точностью.
- Количество токенов (входные, выходные и общие).
- Стоимость выполнения запроса.

## Что сравнивается:
- Скорость обработки запроса.
- Ресурсоёмкость и финансовые затраты.
- Качество ответов (логика, глубина и структура).

## Структура проекта
- main.py — основной Python-скрипт, который выполняет запросы, замеряет метрики и автоматически генерирует отчеты.
- run.sh — управляющий Bash-скрипт для настройки переменных окружения, установки зависимостей и быстрого запуска.
- day5_metrics_report.md — технический отчет с сырыми данными и сводной таблицей метрик.
- answer_comparison.md — итоговый аналитический файл со сравнением скорости, ресурсов, качества, кратким выводом и ссылками.

## Инструкция по запуску
1. Подготовка конфигурации
Откройте файл run.sh и укажите ваш личный API-ключ в переменной LITELLM_API_KEY:
```
export LITELLM_API_KEY="your_actual_api_key_here"
```
2. Запуск эксперимента
Выполните в терминале всего одну команду для установки зависимостей и запуска расчетов:
```
bash run.sh
```

После завершения работы скрипта в корневой папке проекта появятся два готовых отчета: day5_metrics_report.md и answer_comparison.md.

### Итоговый вывод
- Слабые модели обеспечивают мгновенный отклик и минимальные затраты, но подходят преимущественно для шаблонных задач.
- Средние модели удерживают оптимальный баланс между качеством генерации, приемлемой скоростью и стоимостью.
- Сильные модели требуют больше времени и ресурсов, но незаменимы для сложных логических цепочек и глубокого анализа.
