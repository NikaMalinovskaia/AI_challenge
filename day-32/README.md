# 🔥 AI Challenge — День 32. Автоматизация ревью кода

Автоматизированный CI/CD пайплайн на базе **GitHub Actions** и **LLM API**, который анализирует `git diff` при создании/обновлении Pull Request и генерирует профессиональный AI Code Review с учетом контекста правил проекта.

---

## 🎯 Цели и задачи дня

* **Автоматический запуск:** Запуск CI/CD пайплайна при наступлении событий `pull_request` (открытие, новое коммит-обновление) или по ручному триггеру.
* **Сбор изменений:** Извлечение точного `git diff` между веткой Pull Request и основной веткой (`origin/main`).
* **Контекстный RAG-анализ:** Проверка кода на соответствие стандартам архитектуры, безопасности и стиля, заложенным в системном промпте.
* **Структурированный отчет:** Автоматическая генерация отчета с выявлением критических багов, уязвимостей и архитектурных проблем.

---

## 🛠 Архитектура решения

Решение состоит из двух ключевых компонентов:

1. **`ai_review_pipeline.py`** — Python-скрипт анализа:
   * **`get_git_diff()`**: Выполняет команды `git fetch` и `git diff origin/main...HEAD`, автоматически обрабатывая крайние случаи (fallback на `HEAD~1`).
   * **RAG Context**: Передает модели стандарты разработки (запрет сырых SQL-запросов, обязательная параметризация от SQLi, использование контекстных менеджеров `with` для DB-соединений).
   * **Безопасность**: Лимитирует размер передаваемого diff (`MAX_DIFF_CHARS = 50 000`) во избежание выхода за контекстное окно LLM.
   * **LLM Integration**: Взаимодействует с API LiteLLM (`glm-5.3-flash`) через OpenAI Python SDK с `temperature=0.2`.

2. **`.github/workflows/ai-review.yml`** — GitHub Actions Workflow:
   * Настраивает окружение `ubuntu-latest` с Python 3.10.
   * Делает `actions/checkout` с глубиной `fetch-depth: 0` для правильного расчета diff.
   * Передает секреты (`OPENAI_API_KEY`) и параметры подключения в переменные окружения.

3. **`user_service.py`** — Тестовый модуль (демонстрация проблемного кода):
   * Содержит нарочно внедренную SQL-инъекцию (f-строка в SQL-запросе) и незакрытое соединение с БД для проверки работы ревьюера.

## 🚀 Запуск и локальная проверка

### 1. Переменные окружения

Перед запуском установите переменные окружения:

```bash
export OPENAI_API_KEY="ваш_llm_api_key"
export LLM_BASE_URL="https://llm.effective.land/v1"
export LLM_MODEL="glm-5.3-flash"
```

### 2. Запуск пайплайна локально

```bash
python3 ai_review_pipeline.py
```

## 🧪 Пример итогового AI Code Review

Пайплайн возвращает отчет по следующей структуре:

1. **🎯 Общее резюме изменений:**
   * Добавлен модуль `user_service.py` с функцией получения данных пользователя `get_user_data(user_id)`.
2. **🐛 Потенциальные баги и уязвимости:**
   * **SQL Injection:** Использование f-строки `f"SELECT * FROM users WHERE id = {user_id}"` позволяет выполнить произвольный SQL-код.
3. **🏗 Архитектурные проблемы и Code Smells:**
   * **Нарушение паттерна Repository:** Прямой вызов `sqlite3.connect` внутри бизнес-логики.
   * **Утечка ресурсов:** Соединение `conn.close()` не гарантировано при возникновении исключения в `cursor.execute`.
4. **💡 Рекомендации по улучшению:**
   * Переписать запрос с параметризацией: `cursor.execute("SELECT * FROM users WHERE id = ?", (user_id,))`.
   * Использовать контекстный менеджер: `with sqlite3.connect('database.db') as conn:`.
