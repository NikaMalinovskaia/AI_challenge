# 🔥 AI Challenge — День 34. Ассистент для работы с файлами проекта

Автономный AI-ассистент, способный самостоятельно исследовать репозиторий, читать и анализировать исходные файлы, а также генерировать или обновлять документацию на основе высокоуровневых целей пользователя.

## 📁 Структура проекта

```
AI-34/
├── file_agent.py              # Автономный CLI-агент для работы с файлами
├── support_mcp_server.py      # MCP-сервер с инструментами для файловой системы (list, read, write)
├── support/
│   └── faq/
│       └── general.md         # Пример документации / базы знаний
└── data/
    └── tickets.json           # Данные CRM (для проверки инструментов CRM)
```

## 🚀 Реализованные возможности и сценарии

1. 🔍 **Автономное исследование репозитория**: Ассистент не требует вызова типа *"открой файл X"*. Вы задаете абстрактную инженерную цель, а агент сам сканирует директорию (`list_directory`), находит целевые файлы и считывает их содержимое (`read_file_content`).
2. 📝 **Генерация архитектурной документации (ADR / Architecture / README)**: Ассистент анализирует код нескольких файлов в проекте и на их основе генерирует или обновляет итоговые файлы проекта через инструмент `write_file_content`.
3. 🔄 **Автоматическое проведение ревью и проверок**: Способность найти места использования компонентов/API, проверить их соответствие правилам и зафиксировать выводы в файл.
4. ⚙️ **Протокол MCP over Stdio**: Взаимодействие с файловой системой происходит изолированно и стандартизированно через вызовы JSON-RPC MCP-инструментов.

---

## 🛠 MCP Инструменты (`support_mcp_server.py`)

* `list_directory` — просмотреть список файлов и директорий проекта.
* `read_file_content` — прочитать содержимое указанного файла.
* `write_file_content` — создать новый файл или обновить существующий.
* `support_create_ticket` — зафиксировать тикет/обращение в CRM (при необходимости).

## 💻 Инструкция по запуску

### 1. Настройка окружения

Задайте переменные окружения в терминале:

```bash
export OPENAI_API_KEY="your-api-key-here"

# Опциональные параметры (если используется прокси или сторонний провайдер):
export LLM_BASE_URL="https://llm.effective.land/v1"
export LLM_MODEL="glm-5.3-flash"
```

### 2. Запуск агента

Запустите скрипт `file_agent.py`:

```bash
python3 file_agent.py
```

## 💡 Примеры сценариев использования

### Сценарий 1: Автоматическое создание архитектурного описания (ARCHITECTURE.md)

1. **Входная цель пользователя:**
   > `Проанализируй все Python-файлы и создай файл ARCHITECTURE.md с описанием структуры сервера и агента.`

2. **Действия агента (выполняются автоматически):**
   * Вызывает `list_directory` для поиска всех файлов проекта.
   * Вызывает `read_file_content` для `support_mcp_server.py` и `file_agent.py`.
   * Анализирует архитектуру, связи между компонентами и используемый протокол JSON-RPC.
   * Вызывает `write_file_content("ARCHITECTURE.md", ...)` и сохраняет сгенерированную документацию.

---

### Сценарий 2: Поиск использования компонентов и подготовка отчета

1. **Входная цель пользователя:**
   > `Найди все места, где используется функция support_create_ticket, и составь отчет в файле ISSUES_REPORT.md.`

2. **Действия агента (выполняются автоматически):**
   * Сканирует каталог проекта.
   * Читает исходные файлы и ищет упоминания функции `support_create_ticket`.
   * Генерирует отчет с указанием файлов и строк, создавая `ISSUES_REPORT.md`.

## 🔄 Воспроизводимость

Все результаты работы агента сохраняются непосредственно в файловую систему проекта в виде стандартных Markdown-файлов, что позволяет повторно запускать проверки и интегрировать агента в CI/CD процессы.
