# 🔥 AI Challenge — День 33. Ассистент поддержки пользователей

Сервис технической поддержки с интегрированной базой знаний (RAG) и подключением к CRM через протокол MCP (Model Context Protocol over Stdio).

---

## 📁 Структура проекта (Вариант 1: CLI Multi-tool)

Минимальный набор файлов, необходимый для работы ассистента поддержки:

```text
AI-33/
├── support/
│   └── faq/
│       └── general.md         # База знаний и FAQ по продукту (RAG)
├── data/
│   └── tickets.json           # JSON-база данных CRM (пользователи и тикеты)
├── support_mcp_server.py      # MCP-сервер (предоставляет инструменты CRM и чтения файлов)
└── support_agent.py           # Интерактивный CLI-агент поддержки с multi-step tool calling
```

---

## 🚀 Возможности и реализованные требования

- 📚 **RAG (Retrieval-Augmented Generation)**: Ответы на вопросы пользователей с использованием официальной базы знаний (`support/faq/general.md`).
- 🎫 **Автоматическое создание тикетов**: Если у пользователя нет открытого обращения, агент автоматически заводит новый тикет в CRM через вызов инструмента `support_create_ticket`.
- 🔍 **Контекст тикета и CRM**: Просмотр статусов и деталей тикетов с помощью инструмента `support_get_ticket`.
- 🛠 **Диагностика проблем по коду**: Возможность просматривать структуру директорий (`list_directory`) и читать файлы проекта (`read_file_content`) прямо из MCP-сервера для решения технических проблем.
- 🔄 **Multi-step Tool Calling**: Агент способно последовательно вызывать несколько MCP-инструментов за один диалоговый шаг до формирования окончательного ответа.

---

## 🛠 MCP Инструменты (`support_mcp_server.py`)

1. `support_list_tickets` — Получить список всех тикетов.
2. `support_get_ticket` — Получить информацию о тикете по его `ticket_id`.
3. `support_create_ticket` — Зарегистрировать новое обращение пользователя.
4. `list_directory` — Просмотреть содержимое директорий.
5. `read_file_content` — Прочитать содержимое указанного файла.

## 💻 Инструкция по запуску и проверке

### 1. Настройка окружения

Задайте необходимые переменные окружения в терминале:

```bash
export OPENAI_API_KEY="your-api-key-here"
# Опционально (если используется прокси или сторонний LLM-провайдер):
export LLM_BASE_URL="https://llm.effective.land/v1"
export LLM_MODEL="glm-5.3-flash"
```

### 2. Запуск агента поддержки

Запустите интерактивный CLI-скрипт:

```bash
python3 support_agent.py
```

## 💡 Пример сценария взаимодействия

1. **Вход в систему:**
   ```text
   --- 🤖 Инициализация технической поддержки с MCP-доступом к коду ---
   Введите ваш ID (например, u-105): u-105
   Введите ваше имя: Алексей
   Введите номер тикета, если он уже есть (или оставьте пустым): 
   ```

2. **Запрос пользователя:**
   ```text
   Вы: Почему не работает авторизация по корпоративной почте?
   ```

3. **Обработка агентом:**
   - Агент определяет, что номер тикета не был указан, и вызывает MCP-инструмент `support_create_ticket`.
   - Затем обращается к базе знаний RAG (`support/faq/general.md`).
   - Формирует информативный ответ с указанием созданного тикета и решением проблемы.

4. **Вывод:**
   ```text
   🔌 [MCP Action] Вызов инструмента 'support_create_ticket' с аргументами {'user_id': 'u-105', 'user_name': 'Алексей', 'issue': 'Не работает авторизация по корпоративной почте'}

   💬 Поддержка: Здравствуйте, Алексей! Я зарегистрировал ваше обращение под номером T-1001.
   По вашему вопросу: Убедитесь, что ваш домен корпоративной почты подтвержден администратором организации. Также проверьте корректность токена сессии.
   ```
