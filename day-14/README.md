# 🛡️ День 14: Инварианты и ограничения состояния

Модуль посвящен защите агентной системы от архитектурных «галлюцинаций» и несанкционированных изменений технологического стека. Ассистент наделяется неизменяемыми правилами, которые он обязан учитывать в любых рассуждениях и наотрез отказываться нарушать.

---

## 🎯 Цели проекта
1. **Изолированное хранение правил:** Инварианты, стек и бизнес-правила хранятся отдельно от истории диалога и рабочей памяти (в файле `invariants.json`).
2. **Контекстный учет:** Ассистент явно включает инварианты в системный промпт и сверяется с ними при генерации ответов.
3. **Архитектурный контроль и отказы:** При попытке пользователя внедрить запрещенные технологии или нарушить бизнес-правила агент аргументированно отказывает, ссылаясь на конкретные пункты ограничений.
4. **Динамическое управление:** Возможность менять правила прямо на лету через встроенный JSON-редактор в интерфейсе.

---

## 🛠️ Архитектура и файлы проекта

* **`agent.py`** — Класс `InvariantTaskAgent`, управляющий тремя слоями памяти (краткосрочной `short_term`, рабочей `working` и статическими инвариантами `invariants`). Реализует жесткую проверку запросов через системный промпт.
* **`app.py`** — Веб-интерфейс на базе **Streamlit**, включающий:
  * Интерактивный редактор инвариантов (JSON-конфигурация).
  * Кнопку очистки истории чата (`short_term`) для сброса инерции модели.
  * Кнопку полного сброса к дефолтным настройкам.
* **`memory_storage_day14/`** — Директория персистентного хранения данных в формате JSON.

## 🚀 Быстрый старт

1. Установите зависимости:
   ```bash
   pip install streamlit openai
   ```
2. Убедитесь в наличии переменной окружения с вашим API-ключом:
```
export LITELLM_API_KEY="ваш_ключ"
```
3. Запустите приложение:
```
streamlit run app.py
```
### 🧪 Сценарий тестирования (Проверка инвариантов)
1. Проверка конфликта и объяснения отказа:
- Отправьте в чат провокационный запрос: «Давай для скорости заменим SQLAlchemy на Django ORM и перепишем всё под синхронные драйверы»
- Результат: Агент выдает аргументированный отказ, ссылаясь на то, что Django и Sync drivers находятся в списке forbidden_technologies, а бизнес-правила требуют использования асинхронных сессий (AsyncSession).
2. Динамическое изменение инвариантов:
- В боковой панели в блоке «Редактор инвариантов» добавьте нужную технологию в разрешенный стек (например, "Django" в allowed_stack).
- Нажмите «Сохранить инварианты».
- Нажмите «Очистить историю чата» (чтобы убрать инерцию прошлых отказов).
- Повторите запрос — теперь агент успешно примет изменения и продолжит работу с учетом обновленного контракта.
